# notes-api list-notes performance — 2026-05-26 (Worked Example)

> **This is a sample perf report**, the format Phase 11 capstone deliverables
> should follow.

## Methodology

```yaml
Hardware:
  - load_generator:  laptop (Apple M3 Max, 32 GB), wired ethernet
  - target_service:  local notes-api, release build (cargo build --release)
  - database:        local Postgres 17 via compose, default tuning
  - network:         loopback (sub-ms RTT)

Software:
  - target_version:  notes-api commit 8e0f980 (Phase 7 state)
  - load_tool:       oha 1.5.0

Dataset:
  - seeded with `cargo run -p notes-api --bin notes-seed -- --profile load --count 100000`

Procedure:
  1. Restart service.
  2. Warmup: 30 s at 10 RPS.
  3. Measurement: 60 s at 50 concurrent.
  4. Capture both client-side and server-side metrics.
```

## Command

```bash
oha -z 60s -c 50 --no-tui http://127.0.0.1:3000/v1/notes
```

```
  CPU:              ~40% (one core)
```

## Hypothesis

The endpoint returns all 100 000 notes serialized to JSON when no
`limit` is provided, despite most callers requesting just the first
page. The serialization dominates the response time.

## Change

PR #4242: lower default `limit` from "no limit" to 20.

```rust
// In src/lib.rs, before:
let mut items = sqlx_notes::list(&s.pool).await?;
if let Some(limit) = q.limit { items.truncate(limit as usize); }

// After:
let limit = q.limit.unwrap_or(20).clamp(1, 100) as usize;
let mut items = sqlx_notes::list(&s.pool).await?;
items.truncate(limit);
```

(In a real change we'd push the LIMIT into SQL too; this change is the
cheap first step to compare.)

## Comparison

| Metric | Before | After | Δ |
|---|---|---|---|
| Throughput | 1 507 RPS | 2 637 RPS | +75% |
| p50 | 28.3 ms | 15.2 ms | −46% |
| p95 | 82.6 ms | 51.0 ms | −38% |
| p99 | 162.4 ms | 112.7 ms | −31% |
| Peak RSS | 85 MB | 52 MB | −39% |

## Conclusion

Ship. Default `limit` of 20 reduces every measured dimension. Update
`docs/perf/budgets.md` *last verified*. Open follow-up issue to push
the limit into SQL (currently we materialize all rows then truncate).
